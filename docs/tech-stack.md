# Tech Stack

## Summary

| Layer | Technology | Version | Notes |
|---|---|---|---|
| Monorepo | pnpm workspaces + Turborepo | pnpm 11 / turbo 2.x | `node-linker=hoisted` required for Expo |
| Web admin | React + Vite | React 19.2 / Vite 8 | |
| Web routing | TanStack Router | v1 (file-based) | Routes in `src/app/routes/`, route tree generated by Vite plugin |
| Mobile | Expo (React Native) | SDK 57 / RN 0.86 | New Architecture only |
| Mobile routing | Expo Router | v57 (SDK-matched) | File-based, routes in `src/app/`. TanStack Router does not support React Native |
| Server state | TanStack Query | v5 | Both apps. Query definitions co-located with features |
| Forms | TanStack Form | v1 | Both apps, paired with zod validation from `@sona/shared` |
| Styling (web) | Tailwind CSS | v4 | Via `@tailwindcss/vite` plugin |
| Styling (mobile) | NativeWind | v5 (preview) + Tailwind v4 | The Tailwind-v4-compatible track; Expo's own tooling uses it for SDK 55+. Pinned `lightningcss@1.30.1` (NativeWind requirement) |
| Validation | zod | v4 | Schemas in `@sona/shared`, shared by both frontends |
| Unit / component tests | Vitest + Testing Library + MSW | Vitest 4 / RTL 16 / MSW 2 | `packages/shared` (node) and `apps/sona.client` (jsdom); API mocked at the network boundary so `@sona/api-client` + TanStack Query run for real. `pnpm test` |
| End-to-end tests | Playwright | 1.62 (Chromium only) | `apps/sona.client/e2e/` against the real admin + API in the `Local` profile; `pnpm e2e`, `@smoke` subset on PRs |
| Backend | ASP.NET Core | .NET 10 | |
| Language | TypeScript | 6.0 | Strict mode everywhere |

## Key decisions

**Monorepo over separate repos.** Both frontends consume the same API and domain types. Shared `packages/` eliminate contract drift; one PR can change API + web + mobile together.

**Expo over bare React Native.** Official recommendation for all new RN projects. EAS handles builds/OTA updates/store submission. New Architecture is the only option as of SDK 55+.

**Expo Router on mobile instead of TanStack Router.** TanStack Router is web-only. Expo Router is the RN equivalent (file-based, same mental model).

**NativeWind v5 preview over v4 stable.** v4 requires Tailwind v3, which would split Tailwind versions across apps. v5 aligns both apps on Tailwind v4 and is what Expo's official tooling scaffolds. Risk accepted: preview status; revisit when v5 goes stable.

**Shared packages consumed as TypeScript source.** `@sona/shared` and `@sona/api-client` export raw `.ts` — no build step. Vite and Metro both compile workspace TS directly.

**API client is a thin typed wrapper.** TanStack Query hooks live in each app's `features/*/api/` (per bulletproof-react), not in the shared package — cache/invalidation strategy is app-specific.

## Future considerations

- **OpenAPI codegen**: generate `@sona/shared` types from the ASP.NET OpenAPI document (`openapi-typescript` or NSwag) so the contract is enforced mechanically.
- **Push notifications**: `expo-notifications` + Expo Push Service.
- **SMS**: Webex Connect (Cisco), Send Message API v2. BAA status with Webex/Cisco must be confirmed before production traffic (see [compliance.md](compliance.md)).
- **Auth**: TBD — token retrieval is stubbed in both apps' `lib/api-client.ts`.
